# Iceberg v3 for the schema-evolution demonstration only, with deletion vectors as the constraint

**Status:** accepted

The gold tables stay Iceberg format v2, except `commerce.gold.fact_lineitem`, which moves to v3 with `write.delete.mode` and `write.merge.mode` set to `copy-on-write` so that M17 can demonstrate `add-required-with-default`. The reason v2 is the default is narrower than the earlier record stated: it is not format-version 3 that the pinned ClickHouse 26.8 LTS cannot read, it is a Puffin deletion vector. A live test on a pinned 26.8 binary read a v3 copy-on-write table correctly and failed hard with `BAD_ARGUMENTS` on a v3 table carrying a deletion vector. Because every gold table is `MERGE`-maintained and a merge-on-read row-level operation on v3 produces a deletion vector, every merge-on-read gold table stays v2, and only a table whose row-level operations run copy-on-write can be v3 while remaining readable by the read-through arm.

## Considered options

- **Keep every gold table on v2 and record the gap.** Rejected: `initial-default` and `write-default` are v3-only by construction, so the gap is real, and M17's `add-required-with-default` row would evidence the workaround rather than the capability.
- **Move every gold table to v3.** Rejected: the CDC facts and every other `MERGE`-maintained table run merge-on-read, so they would carry deletion vectors, and ClickHouse 26.8 fails hard on those. It would also make the one-way upgrade total rather than confined to one table.
- **Move `fact_order_line` to v3 instead.** Rejected: it is Flink-upsert-written, and Iceberg upsert requires merge-on-read, so it cannot run copy-on-write and cannot satisfy M17's four read paths.
- **Swap the serving engine for Apache Doris 4.1.** Rejected: it is the only released, local, OSS serving store that reads and writes v3 deletion vectors, but on this host it fits only its documented all-in-one dev container, its v3 DML is labelled experimental, and ClickHouse is named by the posting. Not proportionate to a single schema-evolution demonstration.

## Consequences

`fact_lineitem` becomes the single gold table whose format version differs from the rest, so the one-way upgrade is confined to it. Its row-level operations rewrite data files rather than writing delete files, which changes the Spark path's delete-file evidence and carries a carve-out in ADR-0002; M3's exactly-once-effect claim is unaffected. Copy-on-write rewrites the touched files on every run of a `MERGE ... WHEN NOT MATCHED BY SOURCE THEN DELETE`, which is a cost to budget rather than assert. The M17 gap closes, and the v2 workaround previously recorded in `docs/data-contracts.md` is replaced.

**Trigger for re-review.** When a ClickHouse LTS reads deletion vectors, which is 27.3, expected late March 2027, since new features are not backported to 26.8 and 26.10 is non-LTS with the feature labelled Experimental. Falsifiable test: on that LTS binary, read a v3 table carrying a Puffin deletion vector and assert the correct filtered row set. A secondary, weaker trigger is a Flink upsert-on-v3 integration test at a pinned Iceberg tag, which would remove the writer's unverified status; it rides ADR-0024's existing Iceberg 1.12.0 GA re-review rather than creating a second trigger.

**Documented limitations, not settled facts.** Two items are carried forward as validation work rather than decided. First, the live test read through `icebergLocal` over the filesystem, not through the read-through arm's `DataLakeCatalog` with `catalog_type='rest'` against Polaris, so the REST catalog path is untested; both paths share the Iceberg read code that throws, so the finding is expected to transfer, but it is not evidenced. Second, the Flink v3 upsert writer remains unverified at the pinned tag; only Spark was exercised. Neither limitation reopens the decision, because both would only strengthen it: a REST-path or Flink-path failure would remove a capability, not add a constraint the platform has not already accounted for. Evidence: [Full Iceberg v3 stack review](https://github.com/SoongGuanLeong/de-platform/issues/22) and `docs/research/20-clickhouse-26-8-v3-copy-on-write-live-test.md`.
